# Конверсии: форма заявки и цели в Umami

Дизайн от 5 октября 2026. Подпроект B из роадмапа SEO (см. память
`noda-website-seo-roadmap`). Ветка `conversions` от `main`. Английскую версию
(`Landing.jsx`, `en.js`, `cases.en.js`) работа не трогает.

Спек написан без живого обсуждения с Георгием: он был недоступен. Решения,
которые обычно согласуются вопросом, отмечены как **допущение**.

## Зачем

Сейчас единственный путь заявки — Telegram. Собственник, который не хочет
писать в мессенджер незнакомому человеку, уходит молча. Форма даёт второй путь
с нулевым порогом, а цели в Umami показывают, какой путь работает и какие
кейсы и статьи ведут к заявке.

Успех:
- заявка с сайта приходит Георгию в Telegram за секунды;
- в Umami видно: клики в Telegram, отправленные формы, дочитанные статьи,
  переходы из карточек результатов в статьи;
- ни сборка, ни пререндер, ни проверки соседней сессии не ломаются.

## Форма

Место — блок `#cta` на русской главной (`HomeCTA.jsx`). Форма идёт первой,
кнопка Telegram остаётся под ней как второй путь («или напишите в Telegram»).
Навигация «Обсудить задачу» уже ведёт на `#cta`, отдельный блок не нужен.

Поля:
1. «Как вас зовут» — обязательное.
2. «Телефон или Telegram» — обязательное, одно поле. Принимается телефон
   (не меньше 7 цифр), `@ник`, ник без `@` или ссылка `t.me/...`.
3. «Что отнимает больше всего времени» — одна строка, **допущение:
   необязательное** (меньше трения; Георгий всё равно созвонится).

Состояния: заполнение → отправка (кнопка заблокирована) → «Заявка у Георгия,
ответит в течение дня» или ошибка с прямой ссылкой на Telegram. Ошибки полей
показываются под полем после попытки отправки.

Пререндер: форма рендерится на сервере целиком, без обращений к `window`.
Всё, что зависит от браузера (время открытия формы, `fetch`, Umami), живёт
в эффектах и обработчиках.

## Бэкенд — Cloudflare Worker `noda-lead-form`

Код в `worker/lead-form/`, конфиг `wrangler.toml`. В рамках этой работы
воркер **не деплоится** и ресурсы в Cloudflare не создаются.

Адрес — `https://lead.noda-auto.com` (custom domain воркера; DNS-запись
Cloudflare создаёт сам при `wrangler deploy`). **Допущение:** отдельный
поддомен, а не маршрут на `noda-auto.com/api/...`, потому что основной домен
в Cloudflare стоит без прокси (DNS only) и маршрут воркера на нём не сработает.
Адрес на клиенте — константа в `src/lib/lead.js`, переопределяется
`VITE_LEAD_ENDPOINT` на сборке.

Обработка `POST /`:
1. CORS: разрешены только origin из переменной `ALLOWED_ORIGINS`
   (по умолчанию `https://noda-auto.com`). `OPTIONS` отвечает на preflight.
2. Тело — JSON до 4 КБ.
3. Антиспам (ниже). Отбракованное отвечает `200 {ok:true}` и не шлётся —
   боту незачем знать, что его поймали.
4. Валидация той же функцией, что и на клиенте (`src/lib/lead.js`).
   Ошибка → `400 {ok:false, errors}`.
5. `sendMessage` в Telegram Bot API простым текстом (без `parse_mode` —
   не нужно экранировать ввод). Ошибка Telegram → `502`, клиент показывает
   ссылку на Telegram.

Секреты — только `wrangler secret put`: `TELEGRAM_BOT_TOKEN`,
`TELEGRAM_CHAT_ID`. В репо и коде их нет.

### Антиспам

Выбор: **honeypot + проверка времени заполнения + лимит частоты**, без
Turnstile.

- Honeypot: скрытое поле `website`, недоступное с клавиатуры и для скринридеров.
  Заполнено → тихий отказ.
- Время: клиент шлёт, сколько миллисекунд форма была открыта. Меньше 2,5 с →
  тихий отказ. Человек три поля быстрее не заполнит.
- Лимит: Workers Rate Limiting binding, 5 заявок в минуту с одного IP.
  Отдельного ресурса не требует — объявляется в `wrangler.toml`. Код работает
  и без привязки.

Почему не Turnstile сейчас: нужен виджет в аккаунте Cloudflare (создавать
ресурсы в этой работе нельзя), сторонний скрипт на странице и лишний шаг для
собственника бизнеса. На сайте с десятками посетителей в день спам-боты,
заполняющие JS-формы, маловероятны. Если спам пойдёт — Turnstile добавляется
поверх, не ломая текущую схему.

## Цели в Umami

Общий помощник `track(name, data)` в `src/analytics/track.js`: вызывает
`window.umami?.track` только в браузере и глотает исключения. Все имена
событий — константы в `src/analytics/events.js`, компоненты импортируют их
оттуда; тест проверяет kebab-case, префикс и длину меньше 50 символов.
Схема имён — как у /giorgi: `<страница>-<действие>`. Четыре события /giorgi
(`giorgi-telegram`, `giorgi-write`, `giorgi-consult`, `giorgi-site`) переведены
на модуль без переименования — они уже копят статистику, тест их фиксирует.

Одно имя на действие, место — в свойствах события: в Umami одна цель на имя,
а разбивка по местам видна в свойствах.

| Событие | Свойства | Где |
|---|---|---|
| `home-telegram` | `place`: `cta` / `founder` / `footer` / `form-error` | все ссылки t.me на главной |
| `home-max` | `place`: `founder` | кнопка MAX у основателя |
| `home-lead-submit` | — | форма отправлена успешно |
| `home-lead-error` | `reason`: `network` / `server` / `invalid` | форма не ушла |
| `home-case-article` | `case`: id кейса | «→ Как это сделано» в карточке результатов |
| `blog-article-read` | `slug` | дочитал статью до конца |
| `blog-article-telegram` | `slug` | кнопка Telegram под статьёй |

«Дочитал»: метка-наблюдатель (IntersectionObserver) в конце текста статьи
до блока призыва. Срабатывает один раз на статью и только если читатель
прокрутил страницу — иначе короткая статья на большом экране засчитывалась бы
без чтения. Считается только прокрутка после открытия статьи.

Попутно найдено: роутер сохранял прокрутку при переходе, и статья из карточки
кейса внизу главной открывалась с середины (и сразу «дочитывалась»).
`src/components/ScrollToTop.jsx` возвращает страницу наверх при переходе
по ссылке; «назад» не трогает.

`CaseCard` и `Article` общие с английской версией. Там скрипта Umami нет
(`umamiWebsiteIds.en = null`), вызовы молча ничего не делают.

## Проверки

- `node --test tests/`: валидация заявки, текст сообщения, обработчик воркера
  (CORS, honeypot, время, валидация, отказ Telegram, успех) с подменённым
  `fetch`, имена событий.
- `npm run build` и `npm run build:en` зелёные; `routes.js` и
  `verify-prerender.js` не меняются.
- Форма снята вживую в Playwright на 1280 и 400 px.

## Не входит

Деплой воркера, Turnstile, Яндекс.Метрика, страница о компании, форма
на английской версии.
