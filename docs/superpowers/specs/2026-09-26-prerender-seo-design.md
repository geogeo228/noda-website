# Пререндер и техническое SEO

Дизайн от 26 сентября 2026. Подпроект A из четырёх (см. «Место в общей работе»).
База — ветка `en-version`, работа ведётся в ветке `seo-prerender`.

## Зачем

Сервер отдаёт `<div id="root"></div>` и бандл. Контент появляется только после
выполнения JS. Google это умеет, но в два прохода, и очередь на рендеринг может
тянуться днями. Яндекс рендерит JS выборочно и нестабильно. Результат измерен:
в индексе 5 URL из 18, за два месяца 6 кликов и 92 показа, все запросы брендовые.

Пререндер закрывает вопрос сразу для обоих поисковиков и попутно чинит LCP.
Это главный рычаг из `docs/SEO.md`, и до него остальные вложения — контент,
английская версия, ссылки — не окупаются.

## Что считается успехом

- Все страницы из `routes.js` отдаются сервером как готовый HTML с непустым
  `<title>`, корректным `canonical` и текстом в `<body>`.
- Несуществующий URL отдаёт код 404, а не 200 с главной.
- Сборка падает, если хоть одна страница нарушила эти условия.
- В Search Console и Вебмастере количество проиндексированных URL растёт
  к числу страниц в sitemap. Это проверяется за пределами этой работы,
  в подпроекте D.

## Архитектура

`npm run build` становится трёхпроходным.

### Проход 1 — клиентская сборка

Как сейчас: бандл, `sitemap.xml`, `robots.txt`, шаблон `index.html`.

### Проход 2 — серверная сборка

Новый `src/entry-server.jsx` экспортирует `render(url)`: `StaticRouter` и тот же
`App`. Собирается в `dist-ssr/`, в git не попадает, на сервер не уезжает.

В `vite.config.js` добавляется ветка на `isSsrBuild`: при серверной сборке
`sitemapPlugin` не подключается, чтобы не плодить вторую копию sitemap,
и `outDir` равен `dist-ssr`.

Страницы подключены через `lazy()`. Синхронный `renderToString` не станет ждать
динамический импорт и отдаст пустой `<div/>` из `Suspense fallback` — то есть
ровно ту пустую страницу, от которой мы уходим. Поэтому используется
`renderToPipeableStream` с колбэком `onAllReady`: поток дожидается разрешения
импортов и только потом отдаёт разметку. Разметка собирается в строку через
`Writable`. Ни `App.jsx`, ни список маршрутов дублировать не требуется.

### Проход 3 — `scripts/prerender.js`

Импортирует собранный `render`, читает шаблон `dist/index.html`, проходит по
`getRoutes(lang)` и для каждого маршрута пишет `dist/<путь>/index.html`:
тело — из React, `<head>` — из данных.

## Источник правды: `src/routes.js`

Сейчас список маршрутов зашит внутри `sitemapPlugin` в `vite.config.js`.
Выносится в отдельный модуль с единственным экспортом `getRoutes(lang)`,
возвращающим массив объектов:

```
{ path, changefreq, priority, title, description, ogDescription, jsonLd }
```

Статические страницы (`/`, `/blog`, `/giorgi`) берут метатеги из `i18n`,
статьи разворачиваются из `articles` по слагам. Заголовок статьи собирается
здесь же одной строкой: `${article.title} — NODA`.

Модуль читают трое: генератор sitemap, пререндер и проверка на билде.
Страница, добавленная в одном месте, попадает во все три сразу.

Почему метатеги берутся из данных, а не из отрендеренного React через Helmet:
`react-helmet-async` 3.0.0 под React 19 уже один раз молча отдал пустой `<title>`
на всех статьях блога, и мы потеряли на этом индекс. Ставить индексацию сайта
в зависимость от этой библиотеки второй раз не будем. Helmet остаётся работать
только на клиенте — менять заголовок при навигации между страницами.

Цена решения: заголовок страницы описан в двух местах — в `Seo.jsx` для клиента
и в `routes.js` для ботов. Расхождение ловит проверка на билде (пункт 1 ниже).

Попутно чинится баг: `jsonLd` лендинга сейчас хардкодит `url: origins.ru`,
из-за чего в английской сборке организация ссылалась бы на русский домен.
В `routes.js` это становится `origins[lang]`.

## Гидрация

В `main.jsx` — `hydrateRoot` вместо `createRoot`, когда корень не пуст;
при `npm run dev` разметки нет, там остаётся `createRoot`.

Компоненты не меняются. Проверено: `Hero` с эффектом печати, `CountUp`,
`MatrixRain` и время в `Footer` стартуют из детерминированного начального
состояния внутри `useEffect`, поэтому серверная и клиентская разметка совпадают.

## Дубли метатегов

Всё, что пререндер кладёт в `<head>`, помечается атрибутом `data-default-seo` —
тем же, который уже снимает `src/seo-defaults.js` до первого рендера. Клиент
снимает статические теги, Helmet ставит свои, двух `<title>` в отрендеренной
странице не возникает. Механизм существует и работает, он переиспользуется.

## 404

Две дыры закрываются с обеих сторон.

На клиенте: `Article.jsx` при неизвестном слаге сейчас редиректит на `/blog`.
Вместо этого появляется компонент `NotFound` с `<meta name="robots" content="noindex">`,
он же вешается на catch-all роут `*` в `App.jsx`.

На сервере: пререндер генерирует `dist/404.html`, nginx отдаёт его с кодом 404.

## nginx

Ключевое — убрать SPA-fallback. Без этого пререндер обесценивается: любой
несуществующий URL продолжит отдавать главную с кодом 200.

```nginx
root /var/www/html;
index index.html;

location / {
    try_files $uri $uri/index.html $uri/ =404;
}

error_page 404 /404.html;
location = /404.html { internal; }

location /assets/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
}

location ~* \.html$ {
    add_header Cache-Control "no-cache";
}
```

Ассеты у Vite хэшированные, их можно кэшировать навсегда. HTML кэшировать
нельзя — иначе правки статей будут доезжать до читателей непредсказуемо долго.

Клиентская навигация не ломается: переходы внутри сайта делает React Router,
прямой заход на несуществующий адрес отдаёт честный 404.

## Проверки, которые валят билд

Тестового фреймворка в проекте нет, и `vitest` ради этой задачи не добавляется:
проверять надо не функции, а артефакт сборки. `scripts/verify-prerender.js`
запускается последним шагом `npm run build` и при любой ошибке выходит
с ненулевым кодом. В GitHub Actions шаг `npm run build` идёт до rsync,
поэтому битая сборка не доезжает до прода.

Для каждого сгенерированного файла:

1. `<title>` непустой и совпадает с объявленным в `routes.js`.
2. Ровно один `<link rel="canonical">`, его href равен `origin + path`.
3. В `<body>` есть текст, а не пустой `<div id="root"></div>`; порог — 500 символов.
4. `hreflang` присутствует тогда и только тогда, когда `enIsLive === true`.
5. Число сгенерированных файлов совпадает с числом маршрутов и с числом URL
   в `sitemap.xml`.

`404.html` из этих проверок исключён: он намеренно отсутствует в sitemap,
canonical ему не нужен, а вместо пунктов 1, 2 и 5 у него своя проверка —
наличие `<meta name="robots" content="noindex">`.

Пункты 1 и 2 — прямая защита от августовских багов: пустых заголовков
и двойного canonical. Пункт 4 — от разметки, ведущей на неподнятый поддомен.

## Порядок реализации

Проверка пишется первой. На текущем состоянии репозитория она обязана упасть
по пунктам 1 и 3 для всех 18 страниц — это подтверждает, что проблема реальна
и что проверка её видит. Затем пререндер, после которого она проходит.

1. `scripts/verify-prerender.js` — падает на текущем состоянии.
2. `src/routes.js` — вынос маршрутов, `sitemapPlugin` переключается на него.
3. `src/entry-server.jsx` и ветка `isSsrBuild` в `vite.config.js`.
4. `scripts/prerender.js`, сборка `npm run build` из трёх проходов.
5. `hydrateRoot` в `main.jsx`.
6. `NotFound`, catch-all роут, генерация `404.html`.
7. Конфиг nginx на сервере.
8. Прогон `npm run build:en` — английская сборка должна пререндериться тем же кодом.

## Координация

Параллельно сессия `ws_worker` в ветке `case-metrics` от `en-version` правит
кейсы и добавляет страницу `/cases`. Договорённость: она не трогает
`vite.config.js`, а присылает слаги, title и description списком — они
заводятся в `routes.js`. Пересечение только в `App.jsx`: там catch-all роут
против роута `/cases`, строки разные.

## Риски

- **Гидрация разъедется** на компоненте, который окажется недетерминированным.
  Проявится как предупреждение в консоли и перерисовка. Проверяется вручную
  на лендинге и статье после внедрения.
- **`onAllReady` не дождётся** чего-то неожиданного, и в статике окажется
  fallback. Ловится пунктом 3 проверки.
- **Время сборки** вырастет примерно на полминуты. Приемлемо.

## Вне скоупа

Яндекс.Метрика, цели, форма заявки, Cloudflare Worker, страница о компании
и реквизиты — подпроект B. Семантика и статьи Гермеса — C. Недельный дайджест
Ицхака — D. Поддомен `en.noda-auto.com` поднимается после этой работы;
код к нему будет готов, останется переключить `enIsLive` и добавить второй
rsync в воркфлоу.
